## 내용 추가와 검증 방법

새 프레임 17개는 클러스터별로 초안을 쓰고, 별도의 검증 단계가 오류가 있다고 가정하고 다시 확인한 뒤 고쳤다. 검증 단계는 모든 수치를 모듈과 별도로 다시 계산하고(정확한 분수 계산 포함), 프레임의 코드 블록을 실행해 주석의 출력과 비교하고, 인용한 공식 문서를 모두 열어 해당 사실을 확인했다. 이 과정에서 실제 버그도 고쳤다. 예를 들어 6-5의 재인덱싱은 다른 인덱스의 평가 통과 기록을 재사용할 수 있었으나, 이제 평가 보고서의 artifact digest가 새 인덱스와 같아야 하고 `fde.release_gate.evaluate`로 직접 판정한다. 6-6 비용 모델은 모든 비용이 고정비이면 GPU-초가 단가에서 상쇄된다는 점을 바로잡았다. 공식 문서가 해당 사실을 직접 말하지 않거나 열 수 없는 링크는 인용하지 않았다.

면접 후속 질문, 롤플레이, 용어집과 출처 표도 같은 방식으로 작성하고 따로 검증했다. 이후 화면·내용·코드를 네 관점에서 다시 검토했다. 마지막 검토는 네 관점으로 나눴다. 발표자 관점의 화면 검토, OpenAI Codex CLI(0.169)가 화면 16장을 보고 한 시각 검토, Google Antigravity CLI(agy, 1.5.10)가 발표안 전체를 두 번 읽은 내용 일관성 검토, 뷰어와 빌드 코드 검토다. 지적 49건은 고치기 전에 재현했다. 화면 쪽은 검토자가 남긴 재현 스크립트를 수정 후 다시 실행해 해소를 확인했고, 내용 쪽 15건은 수정 단계가 모두 재현한 뒤 고치고 별도 확인 단계가 남은 문제가 없음을 확인했다. 주요 수정은 다음과 같다. 허브 프레임 코드의 가운데 정렬로 깨지던 들여쓰기, 축소(`Esc`·빈 곳·상위 위치 클릭)가 경로를 뒤로 되돌리던 문제, 자유 탐색 직후 다음 단계의 내용이 숨겨지던 타이머 경합, 두 손가락 확대 뒤 카메라가 NaN이 되던 문제, 글꼴 로딩이 도입 비행을 끊던 문제, 발표자 창을 열면 다른 청중 탭끼리 위치를 바꾸던 동기화, 경로를 바꾸면 처음으로 돌아가던 문제, 메뉴·탭·도움말의 키보드 처리, 어두운 테마의 흰 도식, 휴대폰에서 읽을 수 없던 세부 창(이제 시트로 표시), 720p에서 작던 글자(프레임은 원 대신 본문 영역에 맞춰 약 40% 확대)다. 내용에서는 1-1의 공장(site) 범위와 매핑 키, 30분 경로에서 빠졌던 2-3, 1-5 재처리 예제의 실제 출력, 0-1 deadline과 2-2·2-3 고정 시간의 관계(바깥 안전 상한으로 명시), 3-4와 4-2 gate의 관계, 코드에 고정된 제안값의 표기, 역할 지도와 에러 예산 승인자를 맞췄다. 이후 별도 종결 검토가 49건 전부를 현재 빌드에서 다시 판정해 34건 해소, 12건 미해소, 3건 의도한 절충으로 분류했고, 미해소 12건(경로 표시 위 글자, 세부 창 위치, 720p 글자 크기, 휴대폰 조감도·프레임 시트, 공유 주소의 경로 대체, 창 간 테마 동기화, 좁은 발표자 창의 dock, 제안값 표기 등)을 고친 뒤 재현 스크립트로 해소를 확인했다. 이어서 절충으로 두었던 두 가지도 고쳤다. 경로 보기의 정류장에는 1…N 대신 프레임 키를 붙여 주제 번호와 헷갈리지 않게 했고, `retrieve`·`revalidate_evidence`는 요청의 남은 시간을 `timeout_ms`로, ToolBudget은 요청 deadline을 받아 그 안에서 멈추게 했다(테스트 2개 추가). 1-5 코드는 고정용 필드 하나를 빼고 긴 줄을 나눠 24줄·80열 안에 실행 출력 주석 네 줄을 남겼고, 20줄 이상인 코드 창은 여백과 줄 간격을 줄이되 창 테두리와 한글 줄 높이를 높이 예산에 넣어 마지막 줄이 잘리지 않는다. 코드 글자는 720p에서 16.6px, 1600×900에서 21.7px로 읽힌다(창 글꼴 18.1px·23.6px의 0.92배). 그 뒤의 종결 검토 세 번에서 나온 잔여 문제와 수정이 만든 회귀도 고쳤다. 발표자 창은 자신을 연 창(`from=`)의 단계와 시계를 따르고, 그런 창이 없으면 같은 단계를 보는 창, 가장 최근에 조작된 창 순으로 고르며, 열린 직후 누가 이동하면 이전 응답을 버린다. 시계는 실제 조작 때만 시작하고 창을 새로 고쳐도 유지된다. 경로를 바꾸면 이야기 순서에서 같은 위치의 다음 프레임으로 가고, 조감도 단계는 경로 위치(`#경로~단계~위치`)로 구별한다. 결과 단계는 허브와 주제 1~4를 가까이 보는 별도 카메라로 구체적인 결과 문장과 근거 프레임을 보여준다. 경로 선은 원 아래에 그려 주제·허브 글자를 지나지 않는다. 마지막 종결 검토는 49건 전부를 최종 빌드에서 다시 판정해 47건 해소, 1건 절충(1-5 코드 밀도, 이후 위처럼 해소), 1건 미해소(결과 문장의 `게이트·복구` 줄바꿈)로 분류했고, 새 회귀 1건(알 수 없거나 예전 형식의 단계 주소가 결과 단계로 열림)을 찾았다. 둘 다 고친 뒤 재현 스크립트로 해소를 확인했다. 이어서 1-5 코드를 고친 빌드와 그 뒤의 최종 빌드에서 49건을 두 번 더 처음부터 판정했고, 마지막 판정은 49건 모두 해소, 코드 창 34개 전부 세 해상도에서 줄 잘림·줄바꿈 0건이었다. 남은 지적은 핸드아웃 문장 하나의 옛 변수 이름이었고 고쳤다. 예전 주소의 `title`·`canvas`·`cN`은 허브·조감도·주제 N으로 열리고, 알 수 없는 단계는 처음에서 시작한다. codex가 지적한 휴대폰 화면의 프레임 이탈과 제목 겹침은 전환 중에 찍힌 화면이어서 정지 화면에서는 재현되지 않았다.

## 화면 전환 수정 (2026년 11월 18일)

단계를 넘길 때 화면이 크게 깜박이고, 느리고, 자연스럽게 이어지지 않는다는 지적을 받았다. 원인을 측정으로 찾은 뒤 전환을 다시 설계했고, OpenAI Codex CLI와 Google Antigravity CLI(agy)로 동작을 확인했다.

**원인.** 세 가지를 측정으로 확인했다.

- 비행할 때마다 60,000px 캔버스(`#world`)를 `will-change`로 별도 합성 층에 올렸다가 착륙 때 내렸다. 그래서 이륙과 착륙 때 Chrome이 캔버스 전체를 다시 래스터했다. 화면이 멈췄다가 튀었고(애니메이션 프레임 공백 최대 3.4초), 흐리게 날아간 화면은 착륙 뒤에야 선명해졌다.
- 보일 내용을 단계 클래스로 정하고 0.6초 CSS 페이드로 바꿨다. 그래서 내용이 카메라가 멈춘 뒤에야 바뀌었다. 착륙 뒤에도 최대 1.8초 동안 화면이 바뀌었고, 닫는 단계로 갈 때는 1.5초 동안 빈 화면이 나왔다.
- 비행 시간이 0.72~2.6초였다. 천천히 출발하는 곡선(cubic in-out)이어서 처음 10%는 거의 움직이지 않았다.

**새 설계** (`web/atlas.js`).

- `#world`는 합성 층으로 올리지 않는다. 한 애니메이션 루프가 비행, 휠 확대, 닫는 단계 전환을 모두 그리고, 매 프레임 그 배율로 선명하게 그린다.
- 화면에 보이는 내용(확대 단계별 표시)은 카메라만으로 정해진다. 키, 휠, 핀치가 같은 위치에서 같은 내용을 보여 주고, 카메라가 멈춘 뒤에는 아무것도 바뀌지 않는다.
- 비행은 van Wijk 경로를 따라 0.6~1.4초 걸린다. 누르자마자 출발해 부드럽게 내려앉는다. 키를 연달아 누르면 앞 비행의 속도를 이어받아 끊기지 않는다.
- 펼쳐 보일 주제와 프레임(주인공)은 비행 중에 출발점과 도착점으로 고정하고 한 번만 넘긴다. 도착점은 일찍 잡고 출발점은 늦게 놓는다. 그래서 지나가는 주제가 열리지 않고, 출발 주제가 화면을 채운 채 닫히지도 않는다. 조감도나 결과 단계처럼 주제를 열지 않는 도착점은 주인공이 없다.
- 주제가 열리거나 닫힐 때는 표지 제목이 먼저 사라진 뒤 프레임 이름과 설명이 나타난다. 두 글이 반투명하게 겹치는 순간이 없다.
- 휠과 핀치:
  - 노치마다 부드럽게 이어서 확대한다.
  - 손을 떼면 이름과 본문이 반쯤 겹친 확대 단계에 멈추지 않는다. 가던 방향으로 그 단계 끝까지 감속하며 가고, 다시 빨라지지 않는다.
  - 0.15 log2 미만의 작은 움직임은 가까운 쪽 끝으로 돌아간다.
  - 자유 탐색으로 주제 가장자리에 멈추면, 그 주제를 완전히 열거나 완전히 닫는다.
  - 주제를 열고 닫는 기준은 지금 화면 중심이 아니라 확대가 멈출 위치다. 입력이 이어지는 동안에는 그 위치가 100ms 넘게 머문 주제만 연다. 확대해 들어갈 때는 포인터 아래 지점까지 덮는 주제만 미리 열고, 축소할 때는 카메라가 실제로 주제를 벗어나거나 확대가 멈춘 뒤에 닫는다. 그래서 지나치기만 하는 주제가 열렸다 닫히지 않고, 휠을 뺐다 다시 넣어도 머물던 주제가 닫히지 않는다.
  - 감속 중에 넣은 노치와 핀치는 멈춰 있을 때와 같은 빠르기로 반응한다. 반대 방향 입력은 그 자리에서 바로 돌아선다.
- 닫는 단계:
  - 허브 제목과 메시지가 한 자리를 차례로 쓴다.
  - 비행이 중단되거나 다시 시작돼도 제목이 다시 튀어나오지 않는다.
  - 결과 알약은 하단 dock과 겹치지 않는다(12~28px 여백).
- 끊긴 비행이 눌러 두던 허브 제목, 주제 표지, 주제 밝기는 다음 키·휠·드래그가 이어받아 450ms에 걸쳐 푼다. 그래서 키를 연달아 누르거나 입력을 바꿔도 한 프레임에 켜지는 것이 없다.
- 발표자 창과 청중 창은 화면 중심 아래 주제와 허브의 열림 상태를 먼저 맞추고, 그 범위 안에서 조감도 단계를 맞춘다. 모양이 다른 창이라도 같은 주제가 한쪽에서만 열리지 않는다. 주변 주제가 물러나는 정도는 창 모양에 따라 다를 수 있다.

- 면접 15분 경로 20단계에서 주제 단위 깜박임(300ms 안에 0.25 이상 내려갔다 돌아오는 변화)은 0건이다. 남은 오르내림은 의도한 것 하나다. 주제를 옮길 때 카메라가 물러나면 출발·도착 주제의 설명이 잠깐 보인다. 이 변화는 300ms에 걸쳐 일어나고 한 프레임에 0.21을 넘지 않는다.

## 검증의 적용 범위

로컬 결과는 핵심 로직과 명시된 경계를 검증한 것이다. 실제 고객 데이터의 품질, 한국어 embedding·reranker·LLM 성능, 대규모 검색의 recall과 latency, 실제 GPU의 처리량과 대기열, 실제 가격을 측정한 결과는 아니다. 3부의 Erlang C·필터 검색·비용 계산은 가정 아래의 산술이며 부하 시험과 고객 가격으로 바꿔야 한다. `guardrails`는 인용 provenance를 확인하지만 의미적 support를 증명하지 않고, `provenance.py`는 차이가 처음 난 경계를 알려 줄 뿐 근본 원인을 확정하지 않는다.

Kubernetes와 CI 설정은 예제다. 실제 cluster의 admission·CNI 통신, 내부 TLS와 IdP, 인터넷 차단 cold start, WORM 감사 보관, backup/PITR·canary와 원격 GitHub Actions 실행은 이 로컬 검증에 포함되지 않는다. 전체 고객 플랫폼 배포나 네이티브 Prezi 프레젠테이션 생성을 완료했다고 주장하지 않는다. 줌 아틀라스는 브라우저에서 발표하는 구현이며, Prezi 계정에 올리려면 발표안과 PNG를 Prezi에 배치한다. 롤플레이의 30초 답변 길이는 음절 수로 추정한 값이므로 소리 내어 한 번 재야 한다.
