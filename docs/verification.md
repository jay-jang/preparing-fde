## 내용 추가와 검증 방법

새 프레임 17개는 클러스터별로 초안을 쓰고, 별도의 검증 단계가 오류가 있다고 가정하고 다시 확인한 뒤 고쳤다. 검증 단계는 모든 수치를 모듈과 별도로 다시 계산하고(정확한 분수 계산 포함), 프레임의 코드 블록을 실행해 주석의 출력과 비교하고, 인용한 공식 문서를 모두 열어 해당 사실을 확인했다. 이 과정에서 실제 버그도 고쳤다. 예를 들어 6-5의 재인덱싱은 다른 인덱스의 평가 통과 기록을 재사용할 수 있었으나, 이제 평가 보고서의 artifact digest가 새 인덱스와 같아야 하고 `fde.release_gate.evaluate`로 직접 판정한다. 6-6 비용 모델은 모든 비용이 고정비이면 GPU-초가 단가에서 상쇄된다는 점을 바로잡았다. 공식 문서가 해당 사실을 직접 말하지 않거나 열 수 없는 링크는 인용하지 않았다.

면접 후속 질문, 롤플레이, 용어집과 출처 표도 같은 방식으로 작성하고 따로 검증했다. 이후 화면·내용·코드를 네 관점에서 다시 검토했다. 마지막 검토는 네 관점으로 나눴다. 발표자 관점의 화면 검토, OpenAI Codex CLI(0.169)가 화면 16장을 보고 한 시각 검토, Google Antigravity CLI(agy, 1.5.10)가 발표안 전체를 두 번 읽은 내용 일관성 검토, 뷰어와 빌드 코드 검토다. 지적 49건은 고치기 전에 재현했다. 화면 쪽은 검토자가 남긴 재현 스크립트를 수정 후 다시 실행해 해소를 확인했고, 내용 쪽 15건은 수정 단계가 모두 재현한 뒤 고치고 별도 확인 단계가 남은 문제가 없음을 확인했다. 주요 수정은 다음과 같다. 허브 프레임 코드의 가운데 정렬로 깨지던 들여쓰기, 축소(`Esc`·빈 곳·상위 위치 클릭)가 경로를 뒤로 되돌리던 문제, 자유 탐색 직후 다음 단계의 내용이 숨겨지던 타이머 경합, 두 손가락 확대 뒤 카메라가 NaN이 되던 문제, 글꼴 로딩이 도입 비행을 끊던 문제, 발표자 창을 열면 다른 청중 탭끼리 위치를 바꾸던 동기화, 경로를 바꾸면 처음으로 돌아가던 문제, 메뉴·탭·도움말의 키보드 처리, 어두운 테마의 흰 도식, 휴대폰에서 읽을 수 없던 세부 창(이제 시트로 표시), 720p에서 작던 글자(프레임은 원 대신 본문 영역에 맞춰 약 40% 확대)다. 내용에서는 1-1의 공장(site) 범위와 매핑 키, 30분 경로에서 빠졌던 2-3, 1-5 재처리 예제의 실제 출력, 0-1 deadline과 2-2·2-3 고정 시간의 관계(바깥 안전 상한으로 명시), 3-4와 4-2 gate의 관계, 코드에 고정된 제안값의 표기, 역할 지도와 에러 예산 승인자를 맞췄다. 이후 별도 종결 검토가 49건 전부를 현재 빌드에서 다시 판정해 34건 해소, 12건 미해소, 3건 의도한 절충으로 분류했고, 미해소 12건(경로 표시 위 글자, 세부 창 위치, 720p 글자 크기, 휴대폰 조감도·프레임 시트, 공유 주소의 경로 대체, 창 간 테마 동기화, 좁은 발표자 창의 dock, 제안값 표기 등)을 고친 뒤 재현 스크립트로 해소를 확인했다. 이어서 절충으로 두었던 두 가지도 고쳤다. 경로 보기의 정류장에는 1…N 대신 프레임 키를 붙여 주제 번호와 헷갈리지 않게 했고, `retrieve`·`revalidate_evidence`는 요청의 남은 시간을 `timeout_ms`로, ToolBudget은 요청 deadline을 받아 그 안에서 멈추게 했다(테스트 2개 추가). 1-5 코드 24줄은 줄 폭이 글자 크기를 정해 720p에서 약 16px로 남고, 휴대폰 시트와 문서에서는 원래 크기로 읽힌다. codex가 지적한 휴대폰 화면의 프레임 이탈과 제목 겹침은 전환 중에 찍힌 화면이어서 정지 화면에서는 재현되지 않았다.

## 검증의 적용 범위

로컬 결과는 핵심 로직과 명시된 경계를 검증한 것이다. 실제 고객 데이터의 품질, 한국어 embedding·reranker·LLM 성능, 대규모 검색의 recall과 latency, 실제 GPU의 처리량과 대기열, 실제 가격을 측정한 결과는 아니다. 3부의 Erlang C·필터 검색·비용 계산은 가정 아래의 산술이며 부하 시험과 고객 가격으로 바꿔야 한다. `guardrails`는 인용 provenance를 확인하지만 의미적 support를 증명하지 않고, `provenance.py`는 차이가 처음 난 경계를 알려 줄 뿐 근본 원인을 확정하지 않는다.

Kubernetes와 CI 설정은 예제다. 실제 cluster의 admission·CNI 통신, 내부 TLS와 IdP, 인터넷 차단 cold start, WORM 감사 보관, backup/PITR·canary와 원격 GitHub Actions 실행은 이 로컬 검증에 포함되지 않는다. 전체 고객 플랫폼 배포나 네이티브 Prezi 프레젠테이션 생성을 완료했다고 주장하지 않는다. 줌 아틀라스는 브라우저에서 발표하는 구현이며, Prezi 계정에 올리려면 발표안과 PNG를 Prezi에 배치한다. 롤플레이의 30초 답변 길이는 음절 수로 추정한 값이므로 소리 내어 한 번 재야 한다.
