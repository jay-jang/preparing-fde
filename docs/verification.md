# FDE 발표 자료 검증 기록

2026년 11월 17일 작업 폴더의 실제 코드와 생성물을 기준으로 확인했다. [발표안](fde-prezi-ko.md)의 제안 목표와 실제 검증 결과를 구분한다. 2026년 11월 16일의 첫 검증(36개 테스트, 14개 프레임) 이후 줌 캔버스, 2부 현장 플레이북과 관련 코드를 추가했다.

## 요구사항과 결과

| 요구사항 | 확인한 결과 |
| --- | --- |
| Prezi 스타일 발표 | `build/pages/index.html`에 줌 캔버스를 구현했다. 조감도 → 영역 → 카드 → 도식·코드로 확대하고, 먼 이동은 잠깐 축소했다가 다시 확대한다. 면접 15분 21단계, 온보딩 전체 63단계, 현장 플레이북 11단계 경로를 제공한다 |
| 목적에 맞는 화면 | 17개 프레임마다 영문 kicker, 한 문장 메시지(최대 53자), 요점 세 개(최대 29자)의 화면 핵심 블록을 두고 긴 분석·대본은 발표자 노트와 핸드아웃으로 보냈다. 면접 경로는 Level 1·2에서 도식, Level 3에서 코드 하나만 확대하고 0-2 조감도의 네 영역 결과로 끝난다 |
| 발표 도구 | 발표자 노트(대본·분석·화면 구성·Q&A 탭, 경로별 시간 예산과 타이머), 별도 발표자 창의 양방향 동기화, 전체 화면, 밝은/어두운 테마, 주소로 단계 공유 |
| 읽히는 도식 | 17개 Mermaid 도식을 가로세로비 1.31~2.78, 폭 1,300px 이하로 다시 배치했다. 줌 캔버스는 인라인 SVG, 핸드아웃과 Prezi 이관은 PNG를 쓴다. 실패 경로는 붉은 점선과 상자로 표시한다 |
| 추가 자료 | 2부 현장 플레이북 3개 프레임(5-1 고객 Discovery, 5-2 오답 신고의 재현, 5-3 용량 산정), 면접 후속 질문 8개, 고객 상황 롤플레이 4개, `fde/provenance.py`·`fde/capacity.py`와 테스트 |
| 실행 코드 | 트랜잭션 수집, 실제 DB RLS와 hybrid ranking, 인용·도구 제한, 개인정보 최소화, 서명 검증, 품질 gate, 재현 기록 비교, 용량 계산 |
| 자동 검증 | 실제 임시 PostgreSQL을 포함한 74개 테스트, skip 없이 모두 통과 |
| 근거 자료 | 공식 문서 21개 링크. 새로 인용한 PostgreSQL PITR과 vLLM 문서 3개는 내용을 직접 열어 확인했다 |

## codex와 agy의 역할

자료 추가와 검토에 OpenAI Codex CLI 0.169와 Google Antigravity CLI(agy) 1.5.9를 사용했다. 두 도구가 만든 초안은 서로 교차 검토하고, 별도 검증 단계에서 수치·코드·링크를 다시 확인한 뒤 반영했다.

| 단계 | codex | agy |
| --- | --- | --- |
| 초안 | 5-2·5-3 프레임, `fde/provenance.py`, `fde/capacity.py`, `tests/test_field_kit.py` | 5-1 프레임, 면접 후속 질문 8개와 롤플레이 4개, 기존 14개 프레임의 화면 핵심 문구 |
| 교차 검토 | agy 초안과 화면 문구 검토 | codex 초안 검토(17개 지적. Little's law의 평균 W, GPU overhead 정의, PITR과 upstream offset 구분, HMAC key ID 등) |
| 최종 검토 | 줌 캔버스 스크린샷 22장으로 화면 명확성 검토 | 통합된 발표안과 README의 일관성 검토 |

검토 의견은 그대로 적용하지 않았다. 사실과 다르거나 근거 없는 제안(예: 출처 없는 vLLM 예약 메모리 설명)은 버렸다. 이 호스트에서는 비특권 user namespace 제한으로 codex의 sandbox가 시작되지 않아, 초안 작성 단계는 sandbox 없이 쓰기 범위를 프롬프트로 제한하고 저장소 백업과 전후 checksum을 남긴 복사본에서 실행했다. codex가 새로 만든 세 파일 외에 저장소 파일이 바뀌지 않았음을 Git `HEAD`와 비교해 확인했다.

실행 결과는 `Ran 74 tests in 1.376s`, `OK`다. [전체 테스트 출력](test-output.txt)에 각 케이스를 기록했다. DB 검사는 개인 임시 Unix socket과 실제 비특권 LOGIN 계정을 사용했고, 종료 후 해당 서버와 데이터를 제거했다.

중요한 검증에는 동시 중복 전달, 역순 이벤트와 tombstone, 동일 event ID의 payload 변경, 감사 insert 실패 시 전체 rollback, tenant·role 경계, 요청 간 identity 초기화, 생성 중 권한 철회·문서 변경의 재검증, 실제 RSA 서명과 변조 실패가 포함된다. 품질 gate는 합성 입력으로 누락·잘못된 값·슬라이스 회귀·과도한 보류·누출·느린 응답을 판정하는 로직을 확인했다. 새 테스트는 재현 기록의 형식 검증과 경계 순서·다른 tenant 거부, 용량 계산의 정확한 바이트 값(예: 1,000,000 × 768 × 4 = 3,072,000,000B, 토큰당 KV 131,072B), 줌 캔버스의 프레임 구조·화면 문구 길이·카메라 대상·경로를 확인한다.

줌 캔버스는 headless Chromium으로 따로 확인했다.

- 1440×900, 1280×720, 1920×1080에서 17개 카드의 코드·제목·요점·도식이 넘치거나 잘리지 않음
- 다음·이전, `Shift` 건너뛰기, 조감도와 복귀, 링크, 드래그 이동 유지, 경로별 시간 표시
- 청중 창과 발표자 창의 단계·타이머 동기화와 타이머 초기화 공유
- 어두운 테마, 휴대폰 세로·가로 화면과 노트 시트

## 검증의 적용 범위

로컬 결과는 핵심 로직과 명시된 경계를 검증한 것이다. 실제 고객 데이터의 품질, 한국어 embedding·reranker·LLM 성능, 대규모 검색의 recall과 latency를 측정한 결과는 아니다. `guardrails`는 인용 provenance를 확인하지만 의미적 support를 증명하지 않으며, 이 한계를 확인하는 테스트도 포함한다. `capacity.py`의 결과는 가정 계산이고, `provenance.py`는 차이가 처음 난 경계를 알려 줄 뿐 근본 원인을 확정하지 않는다.

Kubernetes와 CI 설정은 예제다. 실제 cluster의 admission·CNI 통신, 내부 TLS와 IdP, 인터넷 차단 cold start, WORM 감사 보관, backup/PITR·canary와 원격 GitHub Actions 실행은 수행하지 않았다. 전체 고객 플랫폼 배포나 네이티브 Prezi 프레젠테이션 생성을 완료했다고 주장하지 않는다. 줌 캔버스는 브라우저에서 발표하는 구현이며, Prezi 계정에 올리려면 발표안과 PNG를 Prezi에 배치한다. 롤플레이의 30초 답변 길이는 음절 수로 추정한 값이므로 소리 내어 한 번 재야 한다.

Pages 연결의 저장 결과는 도구가 `page_creation_outcome_unknown`으로 반환했다. 동일한 생성 키와 원래 인자로 복구를 시도했지만 성공을 확인하지 못해 Page 링크를 제공하지 않는다. 전체 발표안·코드·도식은 로컬 파일과 ZIP에 들어 있다.
